Abstract

Can an interpretable score prioritize sufficiently visible pages so a top-50 review queue contains more observed decline cases than a transparent baseline? I used the authorized 30,000-page starter snapshot, grouped by 32 pseudonymous clients, with decline defined as the current trend_direction == "down" proxy. A stale-and-visible rule was compared with interpretable models using client-grouped validation and nested model selection. On the audited outer holdout, the selected decision tree measured Precision@50 of 0.540 versus 0.280 for the baseline, an absolute difference of 0.260. This is retrospective decision support for human review, not evidence of future forecasting, causal refresh impact, or production ROI.

Introduction / Problem statement

SEO editors cannot inspect every page equally. A ranked queue can make review time explicit while keeping the final decision with a person. The research question is whether a transparent learned score can rank current decline-associated pages better than a fixed stale-and-visible rule.

Data

The starter release contains 30,000 pseudonymized content pages and 32 clients, one row per page, with trailing-90-day performance and freshness fields. The snapshot supports current-state association only; it does not provide a prospective outcome window. Candidate features were impressions_90d, days_since_last_update, avg_position, ctr, and engagement_rate. trend_direction and trend_pct define the proxy and were excluded; content_id and client_id are identifiers used for output and grouped splits only.

Methodology

The baseline is a transparent visibility/freshness/position/depth score. Logistic regression, decision tree, and random forest were candidates. ML-09 selected the decision tree inside an inner client-grouped split and evaluated it once on a disjoint outer client holdout. Preprocessing imputed numeric fields within the training pipeline. Precision@50 is the fraction of observed decline labels among the 50 highest-ranked pages.

Limitations and honest framing

  • Observed decline is a current proxy, not a future outcome.
  • Results are retrospective and may vary by client or time.
  • The original ML-08 holdout was used for model selection; ML-09 corrected this with nested grouping.
  • Ranking does not establish that refreshing content causes improvement.
  • Human review is required; no production ROI or traffic uplift was measured.

Ranked recommendations

The ML-10 queue assigns a priority score, evidence-backed reason code, action label, uncertainty note, and mandatory review status. Editors should verify live relevance, metric completeness, intent, seasonality, effort, and client approval. Escalate missing metrics, very low visibility, recent major changes, legal/brand review, contradictions, duplicate pages, or target-derived evidence. LOW effort covers title/meta review; MEDIUM covers content refresh; HIGH covers ranking investigation. Monitoring covers freshness, missingness, score distributions, client mix, decline rates, acceptance, post-action outcomes, and evaluation deterioration.

Reproducibility

Repository: GitHub source. Run the notebooks in order: w01 through w07, then capstone. Use the project virtual environment and authorized starter data. The public repository contains code and public-safe summaries; private warehouse credentials and raw client records are not required or included. See capstone notebook.

Case study: FlyRank content intelligence

This work turns a content portfolio snapshot into a review queue: visible pages associated with current decline are surfaced with reasons, while editors retain context and veto power. The model measured ranking quality, not the outcome of a refresh. A team could use it to allocate review time, then measure post-action performance prospectively before making stronger claims.
